# FONA AI assistant hardening — Stage 1F A

AI tool execution now inherits the read permissions of the corresponding API and rejects inactive or missing users. Cloud tool declarations are permission-filtered, and local fallback uses the same dispatcher. Private contact details and PPPoE usernames are omitted from optical DTOs. Historical answers whose permission dependencies are no longer allowed are hidden and excluded from model context without deleting the stored messages.

All optical tools use OnuTelemetryView and original sample metadata. Missing, stale, ambiguous, or unverified data never fall back to legacy registration Rx values. N/A retains FONA's Offline display policy while hardware status and freshness remain separate. Ambiguous service searches require explicit selection. Summaries account for every active registration and use actual ticket status values. Critical results include N/A without claiming that an empty result proves the whole network healthy.

Markdown is rendered as React children with validated HTTP(S) links instead of raw HTML. Chat history is server-owned, scoped to the user, bounded, and loaded newest-first before chronological display. Client system roles are rejected. Browser chat storage is removed; account changes remount and cancel stale requests. Clear-history failures retain the visible messages, and deletion shares the same per-user lock as chat.

Cloud adapters normalize both legacy and canonical history formats. Gemini empty argument wire objects remain separate from local arrays, provider signatures are preserved, and parallel function responses are grouped. Errors do not persist implicit model changes. Provider readiness, cloud responses, local lookups, fallback, and unavailable states are distinct. Routine direct lookups read authorized stored data without calling the provider.

Chat has per-user/global request limits, three global processing slots, a per-user lease, bounded tool arguments and rounds, query timeouts, provider cooldown, and a request time budget. Provider errors use safe messages and structured logs. Known credentials and common key formats are redacted; new settings are encrypted. The idempotent ai:encrypt-secrets command protects existing values after a verified backup without changing the logical credentials.

Validation covers permissions, stale/N/A samples, duplicate serials, status totals, ticket filtering, both cloud adapters with mocked responses, server-owned private history, revoked permissions, limits/concurrency, cooldown, and encryption. Browser verification uses synthetic data. Production probes are read-only and explicitly block external generation calls.

Release: publish selected source and tests to GitHub, verify fresh database/application/configuration backups, deploy declared files and assets, reload PHP-FPM, encrypt existing AI settings, then verify unchanged logical credentials and unrelated data. No OLT reader, VPN, firewall, poller, or listener restart is required. Previously deployed frontend source differences are carried forward unchanged so other pages retain their current behavior. Deployment never removes old immutable assets.
