# OLT read coordination — stage 1D-I

Competing FONA reads of the same IP/SNMP port now share a process-owned file lease on the single VPS. Canonical polling, queued SNMP reads, ZTE C300/C320 read methods, forced inventory/port reads, interface probes, ODP reads and alarm confirmation reads use that target lease. Nested synchronous calls in the same process reuse it; unrelated processes cannot. Different targets can still progress independently.

Lease files live outside the application cache. They are never unlinked while a process could own the corresponding inode. OS process termination closes the lease; no cache TTL is used to declare an unfinished read free. Failure to open/lock the coordination file fails closed. This mechanism assumes the current single-host PHP-FPM/CLI deployment and does not provide a distributed lock for multiple servers or independently concurrent tasks within one PHP process.

Production uses different Unix accounts: PHP-FPM uses www-data, polling uses jasenardian and the listener uses root. The directory must be provisioned with the common www-data group and mode 2770; persistent lock files use mode 0660 and retain that group through setgid inheritance. Deployment must test acquisition/contention and release under every actual service account, including pre-existing lock files. Owner-only file modes are insufficient. The initial rollout was rolled back when this difference was found; the corrected rollout adds those cross-account checks.

Manual live requests return HTTP 423 with a retry hint when another read owns the target, or 503 when coordination is unavailable. Cached inventory pages remain readable. Point diagnostics may return their matching stored observation with an explicit busy reason, original source, timestamp and freshness. They never refresh the age of an old sample. Blocked polling is reported BUSY/UNKNOWN and does not count the prior inventory as newly read ONUs or overwrite the prior hardware attempt.

Alarm confirmation and SFP point reads may defer while a poll is active. Missing confirmation is not evidence of an outage or recovery. Incoming trap processing and ordered writes from verified observations remain independent of the SNMP read lease. Basic connectivity checks and external applications reading the OLT are outside this coordination scope; this is not a packet-loss or device-availability guarantee.

The existing four-worker internal queue, scoped PON discovery, per-job/deadline limits, hardware identity checks, raw hardware state, web N/A presentation policy, VPN/firewall and billing rules remain unchanged. Legacy import endpoints also gain exclusion at the driver read boundary; this stage does not redesign their earlier import/write behavior.

Before deployment, Linux candidate checks run in memory with database READ ONLY and isolated measurement cache. They verify blocked live requests and polling, preserved snapshot timestamps and automatic lease release after killing the owner process. Regression tests exercise separate processes, nested leases, cache clearing, cached-page availability and accurate BUSY reporting. A frontend message explains the stored fallback.

Two directly confirmed current hardware tuples on OLT 2 still return Online with unavailable Rx. CLI usernames/passwords were absent from all three OLT records when inspected on 17 October 2026, so comparison with CLI was not possible. Sensor invalidity remains separate from timeout/contention; no alternate OID, old Rx value or fabricated measurement is substituted without confirming the sensor contract.
