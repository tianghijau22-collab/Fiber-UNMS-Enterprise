# Per-ONU inventory metadata — stage 1D-B

The partition between customer registrations, physical unregistered ONUs and autofind results used to discard measurement timestamps and state/Rx validity. Registered rows lost the online boolean; physical unregistered rows lost sample metadata and their canonical port. Later reads could not distinguish unavailable state from old or complete observations. Some inventory tables and filters also classified missing Rx as loss.

The partition now preserves the full confirmed tuple and canonical per-ONU sample, state and optical timestamps for both registered and unregistered physical ONUs. Stored unregistered physical rows follow the same projection on subsequent reads. Autofind detection alone remains Unknown without invented state, Rx or measurement time. Missing customers and unverified identities never use registration status as a live ZTE observation.

Snapshot publication accepts detected-port aliases for matching a full tuple, retains an existing explicit per-ONU observation, and never substitutes snapshot completion time when a measurement time is absent. The existing ordering ledger, OLT ownership locks and duplicate-registration protections remain in force. Projection is not an acquisition: a new polling/point/event operation still supplies the actual observation time. No historical timestamps are backfilled.

The shared customer/ODP/GIS reader no longer treats a ZTE legacy snapshot completion time as a per-ONU sample. State and Rx timestamps are checked separately. Data without proof remains unavailable; data older than 180 seconds remains stale; identity proof expires after 600 seconds. Fresh working state without Rx remains Online.

Desktop/mobile inventory tables, filters and optical summaries use the same tri-state presentation. Unknown state and Online without Rx are counted separately from verified Offline and measured optical quality. Weak but valid Rx remains a measurement. Port status cannot infer mass loss from missing state alone. Measurement timestamps remain visible. This does not replace the separate optical diagnostic endpoint/modal or simulated hardware/SFP sensor presentation; those remain separate follow-up work.

Validation includes projection round trips, registered/unregistered samples, missing/future/old metadata, autofind-only detection, inventory refresh, a newer matching ledger observation, customer/ODP/GIS comparison and graph/filter presentation regressions. Production checks use read-only database transactions and isolated caches; ledger replay is an in-memory comparison, not a production repair or a new hardware observation. Rollout requires a verified fresh backup, exact source/assets, reload of long-lived consumers, and observation of normal polling cycles.
