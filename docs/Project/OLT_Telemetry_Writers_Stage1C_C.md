# ONU telemetry writers — stage 1C-C

Status at preparation: tested local candidate; not deployed. This document describes the proposed release, not a production rollout result.

The ZTE live writers use ownership-scoped registrations, full PON/ONU identity and observations whose age is bounded. Serial/MAC aliases that refer to different hardware, multiple matching registrations, deleted customers and foreign OLT registrations cannot select an arbitrary write target. Missing operational state remains Unknown. Working state without optical power stays Online with unavailable Rx; numeric power never establishes recovery or loss.

`OnuTelemetryWriter` commits the per-ONU ordering ledger and eligible registration changes in a database transaction with an OLT row lock. Topology nodes and ports are read under shared locks during the batch to prevent concurrent ownership moves. Observation order uses the beginning of a query or the VPS receipt of an event; equal times prefer event over point over poll. Samples older than 180 seconds and identities older than 600 seconds are rejected. Ordering metadata is bounded to 600 seconds. This is not a vendor event sequence or a device measurement timestamp, and cannot prove chronological delivery of UDP events before they reach the VPS.

`OltDevice::update` merges published snapshots with the current ledger under the same OLT lock. Inventory refreshes, stale model instances, imports and provisioning cannot erase newer accepted measurements or promote preserved values using snapshot completion time. Canonical per-ONU timestamps pass through partitioning, response presentation and point overlays. The read-only ODP status probe remains read-only; only the explicitly writing optical probe uses the guarded writer.

Poll slot/global/port paths, interactive OLT synchronization, individual events and ODP/interface point reads share the guard. A verified physical port-down observation affects only the selected OLT and hardware PON. Physical port-up does not establish that all ONUs have recovered. Interface state parsing requires the exact requested IF-MIB OID and explicit Up/Down values; missing values or matching suffixes from unrelated OIDs do not establish loss. Sessions opened by the physical port probe are closed.

Legacy topology-wide `instantBulkDbSync` calls are retained as non-writing compatibility hooks. Correlation alone cannot promote or drop every customer on an ODP/PON. Confirmed per-ONU producers update eligible registrations; mass outage/recovery decisions from partial ONU reads are held. Recovery events require current serial-confirmed working state. Existing physical-interface alerts remain distinct from per-ONU state; polling cadence is unchanged.

Customer creation/replacement and external imports do not inject synthetic hardware rows or default optical measurements. Import binding is scoped to the selected customer service, refuses ambiguous existing bindings and explicit cross-OLT moves, and creates new records pending verification. Hardware refresh after an import can populate verified telemetry. These changes do not reconcile existing duplicate registrations or missing topology automatically.

Response cache invalidation uses customer v5, GIS v2, hierarchy and dashboard keys after commit. Flap suppression and cooldowns are scoped by OLT/registration, with malformed history treated as empty. Alarm/cache side effects are deferred until outer transaction commit. No sessions are flushed. The interface optical modal and exported screenshot use the shared presentation helper and warn about partial reads; unavailable Rx is not displayed as a sentinel.

Validation covers ownership, alias conflicts, mixed PONs, older polls versus new events, repeated point reads, stale snapshot instances, rollback and outer transactions, malformed flap cache, interface OID/state validation, import binding, honest power availability and read-only probes. The production data comparison uses read-only transactions and an in-memory cache; candidate mutation methods must never be executed against production before approval.

Deployment requires PHP sources and rebuilt web assets, fresh verified backups, targeted cache invalidation, PHP-FPM reload and a controlled restart of long-lived workers. Preserve previous hashed assets and manifests. No schema migration or OLT configuration change is required. Rollback restores application sources/manifests and reloads affected processes; never overwrite live operational data with an old database backup automatically.

Remaining work includes vendor decoder coverage, UDP event chronology, long-run concurrency/load measurements, per-device measurement timestamps, complete administrative provisioning review, duplicate-registration reconciliation, mobile presentation and hardware polling optimization. The guarded mutation/locking path has not been run in production during preparation.
